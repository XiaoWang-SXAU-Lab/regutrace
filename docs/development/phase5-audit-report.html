5.3 审计发现：坐标覆盖不是 30

独立核对 phase5-coord-audit.tsv 得到 52 个 base TFs 的 architecture_groups=0，而非报告早期写的 30。 另有 22 个 coordinate-rerun TFs 不在 1,143-row baseline 内。实际交集为 1,089 TFs（DB 中有坐标的 TF 数）。

影响：52 个 TF 的 best/reps 不能用坐标分组，代码退化为按原始 exploratory 行选一个/每组代表；它们仍被计入 1,143 和 target 统计。这是 P2，已在文档中纠正。

6.3 审计判断

  • P1（科学） site/promoter q 是保守上界：只对 hit 排序，未建模窗口/基因依赖、GC/长度、motif 家族依赖。
  • 已披露 默认 p=1e-4 未变；FDR 仅作为可选解释层，不能替代原始候选背景。
  • 缺口 没有 block/bootstrap 或 dependence-aware null；FIMO 未安装/未执行。

11. 给 ChatGPT 的复核问题

  1. 保守 BH 的公式（hit ranks + complete window universe）是否可作为 Phase 5 的可接受上界？是否应改为 block/bootstrap 或直接报告未校正候选？
  2. DAP-seq 的 positive=promoter overlap、unknown=unobserved 是否足以支持“direct motif 优于 transfer”的相对结论？还缺哪些对照？
  3. 52 个无坐标 TF 的 fallback 处理是否应排除在 best/reps 覆盖之外，还是保留但仍算 coverage？
  4. pairs 仅导出 best policy（7.39M），而 motif_target 保留 4.64M motif 关系，是否满足 rsWGCNA 的“保留原始证据、下游自行过滤”要求？
  5. v2 background 是否应先用完整 1.3 GB 项目导入 + restart 复验，再称为 release-ready？
  6. Phase 6 的 rsWGCNA integration 是否应先解决 dependence-aware statistics，还是先做 expression-only GRN 的证据分层？
